Agent

开始

为了更好地组织智能体的“思考”与“行动”过程，业界涌现出了多种经典的架构范式。这里，将聚焦于其中最具代表性的三种，并一步步从零实现它们：

  • ReAct (Reasoning and Acting)： 一种将“思考”和“行动”紧密结合的范式，让智能体边想边做，动态调整。
  • Plan-and-Solve： 一种“三思而后行”的范式，智能体首先生成一个完整的行动计划，然后严格执行。
  • Reflection： 一种赋予智能体“反思”能力的范式，通过自我批判和修正来优化结果。

为什么要实现

  1. 对Agent的工作流程更加熟悉
  2. 自定义Agent的处理过程，高度定制

ReAct

模型通过 Thought(思考) -> Action(行动) -> Observation(观察)过程来处理用户问题

  • Thought: 分析当前情况、分解任务、制定下一步计划，或者反思上一步的结果
  • Action: 根据前面的分析以及已有工具，给出行为，如调用工具
  • Observation: 观察前一步 Action 的执行结果，判断是否可以解决问题，如果可以，则返回最终回答；如果不可以，则回到 Thought 进行

提示词设计

  1. 定义智能体任务
  2. 定义智能体回答格式
    根据前面ReAct的原理，可以知道，ReAct模式中，模型处理输出的为 Thought和 Action，其中 Thought可以方便使用者明白模型的思考过程，理解模型为什么这么做；Action则是模型需要执行的行为，由于这里要判断是否继续思考，因此这里需要设计两种回答格式，一种是调用工具，另一种则是直接返回答案。
    这里为了解析方便，将两部分内容均放在标签当中，并且Action的格式采用 json 格式
  1. 定义智能体可使用工具
    创建工具注册类ToolRegister，注册可使用工具并传入Agent，然后将工具的描述放入提示词中（如果要运用function call的话则需要将工具转换成对应的json格式）

PlanAndExecute

正如其名称所述，先规划再执行，故这里将问题的处理过程分为三个步骤

  1. Planner: 进行任务规划
  2. Executor: 依次执行对应任务中的每一步

最后一步执行完则得到了最终的结果

但由于计划执行过程中可能会出现错误，故这里可以增加优化步骤

当Executor执行失败或错误后，调用 Replanner，按照当前进行，重新执行制定计划，直至达到最大轮次或解决问题后结束

Reflection

其主要思想即为将整个问题的处理过程分为三块

第一块是任务的首次处理

第二块是处理结果评估(需要判断是否以及完美，如果完美返回固定格式或标记）

第三块是根据评估结果给出进一步优化的结果（没有完成则优化，完成则结束）

取自 Hello Agent的教程

  1. 执行 (Execution)：首先，智能体使用我们熟悉的方法（如 ReAct 或 Plan-and-Solve）尝试完成任务，生成一个初步的解决方案或行动轨迹。这可以看作是“初稿”。
  2. 反思 (Reflection)：接着，智能体进入反思阶段。它会调用一个独立的、或者带有特殊提示词的大语言模型实例，来扮演一个“评审员”的角色。这个“评审员”会审视第一步生成的“初稿”，并从多个维度进行评估，例如：
    • 事实性错误：是否存在与常识或已知事实相悖的内容？
    • 逻辑漏洞：推理过程是否存在不连贯或矛盾之处？
    • 效率问题：是否有更直接、更简洁的路径来完成任务？
    • 遗漏信息：是否忽略了问题的某些关键约束或方面？ 根据评估，它会生成一段结构化的反馈 (Feedback)，指出具体的问题所在和改进建议。
  3. 优化 (Refinement)：最后，智能体将“初稿”和“反馈”作为新的上下文，再次调用大语言模型，要求它根据反馈内容对初稿进行修正，生成一个更完善的“修订稿”。
